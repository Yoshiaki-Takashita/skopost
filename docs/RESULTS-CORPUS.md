## 外れと見つけたことの読み

1. **C3b（外れ）**：「論」は claude-settings（85 件すべて論）と openapi（110 件）から出た。規則の一部は構文上の事実
   （許可リストの道具名・HTTP メソッド）から筋道で導くので「論」を付けている（論）。予言は「説明文由来の推が大半」と
   置いたが、それは mcp だけ（124 件すべて推）に当てはまった。F2（確 0）は守られている。予言の置き方が粗かった（論）。
2. **C6b・C6c（外れ）**：この生成器は道具の 30% が置き場を書く／読む札を持ち、置き場の札を 15% で不明にする
   （`synth` の `p_store_unknown`）。道具が 10〜64 個と多いので、どこか 1 つの置き場の札が不明な構成がほとんどになり、
   monotone の増分が GRAPH.md の数字（tests の分布で +8.6%・245/1,000）より大きくなった（論）。予言は GRAPH.md の
   数字から外挿したが、道具の数と置き場の札の多さを見込めていなかった。monotone の代償は「置き場の札の不明率と
   道具の数に強く依存する」と読むべき（推）。既定を切り替えるかの判断（GRAPH.md「決めてほしい点」）の材料。
3. **C1b の記録漏れ（不具合・直していない）**：`skopost/ingest/openapi.py` は Path Item と Operation の `x-` 拡張を
   notes に書かずに飛ばす（最上位の `x-` は書く）。ARCHITECTURE の I3「読めなかった鍵が 100% 記録される」を
   x- を含めて読むなら**破れている**。全体の記録率は 48+0 / 67＝71.6%。ingest は担当 B の範囲なので直さず記録だけ
   （corpus の性質試験は x- を除外して守り、除外理由をコメントに書いた）。
4. **C5 の注意**：SPEC の道から作る問題は 64 道具でも全部二部（König）で解けた。非二部の最悪形（tests/test_graph_bench の
   general）は合成の SPEC 構成からは出ていない。G2 は「この分布では」当たり（確）、最悪形での保証ではない（不明）。
